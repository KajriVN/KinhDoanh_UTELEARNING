2. Chạy dự án

Cách 1 — chạy nhanh bằng H2 (không cần cài MySQL)

mvn spring-boot:run -Dspring-boot.run.profiles=h2
# hoặc
mvn package -DskipTests
java -jar target/utelearn-0.0.1-SNAPSHOT.jar --spring.profiles.active=h2

Dữ liệu lưu ở data/utelearn-h2.mv.db (đã gitignore). Xóa thư mục data/ để reset. Lần chạy đầu DataSeeder tự tạo dữ liệu mẫu.

Cách 2 — MySQL (cách nộp bài)

  1. Mở MySQL Workbench → chạy database/utelearn.sql (tạo DB utelearn + 17 bảng + dữ liệu mẫu).
  2. Sửa user/pass trong src/main/resources/application.properties hoặc đặt biến môi trường DB_USERNAME, DB_PASSWORD (mặc định root / 123456).
  3. mvn spring-boot:run → mở http://localhost:8080.
Máy dev hiện tại cổng 8080 đang bị chương trình khác chiếm. Chạy với --server.port=8088. File .claude/launch.json đã cấu hình cổng 8088.

Maven: máy này chưa cài mvn vào PATH; có sẵn bản ở ~/.m2/wrapper/dists/apache-maven-3.8.5-bin/*/apache-maven-3.8.5/bin/mvn, hoặc mở bằng IntelliJ.

Cloudinary (tùy chọn)

Đặt CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET. Nếu để trống, FileUploadService lưu file vào uploads/ và phục vụ qua /uploads/** (xem WebMvcConfig).

4. Quy ước code (giữ đúng để code đồng bộ)

Yêu cầu của nhóm: code sạch nhưng đơn giản, kiểu sinh viên — không over-engineer. Cụ thể:

  • Service là class thường (không tách interface + impl). Inject bằng constructor, không dùng @Autowired field.
  • Entity dùng Lombok @Getter @Setter @NoArgsConstructor (không dùng @Data). Tên bảng/cột snake_case khai báo rõ bằng @Table/@Column.
  • Comment tiếng Việt, ngắn, chỉ ở chỗ cần giải thích "tại sao".
  • Lỗi nghiệp vụ: service ném BusinessException("thông báo tiếng Việt") → controller try/catch → redirect.addFlashAttribute("error", e.getMessage()). Thành công thì "success". Fragment flash tự hiện.
  • Không tìm thấy: ném NotFoundException → trang 404. Sai quyền: ném org.springframework.security.access.AccessDeniedException → trang 403. Không bắt 2 loại này trong controller.
  • Lấy user hiện tại trong controller: tham số Principal principal → userService.findByEmail(principal.getName()). Trong template đã có sẵn ${currentUser} và ${cartCount} (GlobalModelAdvice).
  • Kiểm tra quyền sở hữu khóa học: dùng courseService.getOwnedCourse(id, user) / canManage(course, user) (admin luôn được).
  • Form: th:action + method="post" (Thymeleaf tự chèn _csrf). Form có file thêm enctype="multipart/form-data". Validate bằng DTO + @Valid + BindingResult.
  • Hiển thị tiền: ${@fmt.money(x)} / ${@fmt.price(x)} (0 → "Miễn phí"). Ngày: ${@fmt.dateTime(t)}. Phân trang: ~{fragments/layout :: pagination(${page})}.
  • Trang mới copy khung từ trang có sẵn: head(title) → navbar → main (+ flash) → footer. Trang GV/admin có cột trái instructorMenu('key') / adminMenu('key'). Các mục "sắp có" trong menu là chỗ gắn chức năng mới.
  • Upload file: luôn qua FileUploadService (uploadImage, uploadVideo; cần thêm uploadDocument cho bài tập — xem 8.3).
  • Đánh dấu chỗ chưa làm bằng comment // TODO (hand-off): ... — tìm nhanh: grep -rn "TODO (hand-off)" src.

8. Spec chi tiết phần còn lại

Mỗi mục ghi: file cần tạo, route, logic, tiêu chí xong. Làm theo đúng quy ước mục 4.

8.1 Thanh toán VNPay sandbox ưu tiên cao

  • Đăng ký tài khoản test tại sandbox.vnpayment.vn → lấy vnp_TmnCode, vnp_HashSecret. Thêm vào application.properties: vnpay.tmn-code, vnpay.hash-secret, vnpay.pay-url=https://sandbox.vnpayment.vn/paymentv2/vpcpay.html, vnpay.return-url=http://localhost:8080/payment/vnpay-return (dùng biến môi trường, không commit secret).
  • Tạo service/VnPayService: createPaymentUrl(Order, HttpServletRequest) — tham số vnp_Version=2.1.0, vnp_Command=pay, vnp_Amount=finalAmount*100, vnp_CurrCode=VND, vnp_TxnRef=orderCode, vnp_OrderInfo, vnp_OrderType=other, vnp_Locale=vn, vnp_ReturnUrl, vnp_IpAddr, vnp_CreateDate (yyyyMMddHHmmss, GMT+7); sắp xếp key A→Z, URL-encode, ký HMAC-SHA512 bằng hashSecret → vnp_SecureHash.
  • Trang order/payment.html: thêm nút "Thanh toán VNPay" (POST /payment/{code}/vnpay → redirect URL VNPay; set order.paymentMethod=VNPAY). Giữ nút giả lập để demo.
  • GET /payment/vnpay-return: verify chữ ký (bỏ vnp_SecureHash, vnp_SecureHashType), nếu vnp_ResponseCode == "00" và số tiền khớp → orderService.markPaid(order) (đã có, tự ghi danh + xóa giỏ); sai → status=FAILED. Phải permitAll hoặc giữ authenticated (cookie vẫn gửi vì SameSite=Lax với GET top-level).
  • Xong khi: thanh toán bằng thẻ test NCB của VNPay → đơn PAID, khóa vào "Khóa học của tôi"; sửa tham số trên URL return → báo lỗi chữ ký.

8.2 Mã giảm giá

  • Admin: controller/admin/AdminCouponController + templates/admin/coupons.html (CRUD, giống trang danh mục). Bật mục "Mã giảm giá" trong adminMenu.
  • CouponService.validate(code): tồn tại, active, chưa hết hạn, maxUses == 0 || usedCount < maxUses.
  • Giỏ hàng: bỏ disabled ô nhập ở cart/cart.html, form gửi kèm couponCode vào POST /checkout. Trong OrderService.checkout (chỗ có TODO): discount = total * percent / 100 (làm tròn xuống), set order.coupon, discountAmount, finalAmount. Tăng usedCount trong markPaid (chỉ khi thanh toán thành công).

8.3 Bài tập & chấm điểm ưu tiên cao

  • Entity/Repository: Assignment, Submission đã có.
  • FileUploadService: thêm uploadDocument(file, folder) cho đuôi .pdf .doc .docx .zip .rar .txt (Cloudinary dùng resource_type=raw cho file không phải ảnh/video). Giới hạn 20MB.
  • AssignmentService: create/update/delete (chỉ chủ khóa, dùng courseService.getOwnedCourse), submit(student, assignmentId, file, note) (phải enrolled, cho nộp lại nếu chưa chấm và chưa quá hạn), grade(submissionId, score, feedback) (0 ≤ score ≤ maxScore, set gradedAt).
  • GV: /instructor/courses/{id}/assignments (danh sách + form tạo), /instructor/assignments/{id}/submissions (bảng bài nộp + ô chấm điểm). Bật mục "Bài tập & chấm điểm" trong instructorMenu.
  • HV: tab/khối "Bài tập" trong learning/learn.html (chỗ có TODO) hoặc trang /learn/{courseId}/assignments: xem đề, nộp file, xem điểm + nhận xét.
  • Khi xóa bài học có assignment gắn lesson_id: set null trước khi xóa (CurriculumService.deleteLesson / deleteSection).
  • Xong khi: GV tạo bài → HV nộp file → GV chấm → HV thấy điểm; HV chưa mua khóa không nộp được.

8.4 Đánh giá khóa học

  • Chỉ học viên đã ghi danh mới được đánh giá, mỗi người 1 lần (có unique), cho sửa.
  • POST /courses/{id}/reviews (rating 1–5, comment). Hiển thị ở course/detail.html chỗ có TODO: điểm TB (ReviewRepository.averageRating), số lượt, danh sách.
  • Thêm số sao trung bình vào courseCard (cẩn thận N+1 — nên viết 1 query SELECT r.course.id, AVG(r.rating) ... GROUP BY r.course.id).

8.5 Thông báo realtime

  • NotificationService.notify(user, title, content, link): lưu DB + messagingTemplate.convertAndSendToUser(email, "/queue/notifications", dto).
  • Gọi ở: duyệt/từ chối khóa (CourseService.approve/reject có TODO), thanh toán thành công, có tin nhắn mới, bài tập được chấm.

9. Lưu ý / nợ kỹ thuật

Chưa chạy thử trên MySQL thật (máy dev không có MySQL server). File utelearn.sql và app chỉ được kiểm tra trên H2 chế độ MySQL. Việc đầu tiên nên làm: import SQL vào MySQL 8 và chạy smoke test lại.
  • CSRF: bật, token lưu cookie XSRF-TOKEN (CookieCsrfTokenRepository), bỏ qua /ws/** (SockJS). Nếu viết AJAX POST phải gửi header X-XSRF-TOKEN.
  • JWT: hết hạn 1 ngày, không có refresh token; đăng xuất chỉ xóa cookie (token cũ vẫn hợp lệ đến khi hết hạn). Secret mặc định nằm trong properties — khi deploy phải đặt JWT_SECRET.
  • JwtAuthFilter load user từ DB mỗi request để tài khoản bị khóa bị đá ra ngay — chấp nhận được với đồ án.
  • GlobalModelAdvice chạy 2 query (user + đếm giỏ) cho mọi request kể cả POST.
  • spring.jpa.open-in-view=true: template truy cập lazy collection (sections/lessons) thoải mái. Một số trang có N+1 nhỏ (thẻ khóa học gọi getTotalLessons).
  • Chat: tin nhắn của người ngoài cuộc trò chuyện bị chặn (AccessDeniedException) nhưng không có thông báo lỗi trả về client (chỉ BusinessException mới đẩy /user/queue/errors). Simple broker trong RAM — không scale nhiều server.
  • Upload local (khi không có Cloudinary) lưu ở uploads/, đã gitignore. Chỉ nhận đuôi ảnh/video trong whitelist.
  • Xóa khóa học bị chặn nếu đã có ghi danh/đơn hàng; xóa danh mục bị chặn nếu còn khóa học.
  • DataSeeder chỉ chạy khi bảng users rỗng. Nếu thay đổi seed, sửa cả database/utelearn.sql.
  • Chưa có unit test (thư mục src/test trống). Nên thêm test cho OrderService, LearningService, CourseService.
  • Thư mục Tiêu Chí/ (bảng chấm điểm) và tool.txt chưa được commit — để nhóm tự quyết.

11. Đã test những gì

  • Smoke test bằng curl (70 bước): khách, đăng ký/đăng nhập, học viên mua khóa → thanh toán → học → tiến độ, phân quyền 403, admin (user, danh mục, duyệt/từ chối), giảng viên (tạo khóa có upload ảnh multipart, thêm chương/bài, gửi duyệt), link Youtube → embed. Kết quả: tất cả pass (2 lần fail ban đầu là do script test sai kỳ vọng / lỗi mã hóa tiếng Việt của Git Bash, không phải lỗi app).
  • Chat WebSocket: client STOMP Python — HV gửi, GV nhận và ngược lại; người không thuộc cuộc trò chuyện bị chặn.
